# 数据源

数据源是检查所读取的 PostgreSQL 数据库。`DATABASE_URL` 是内置数据源，显示为 **主库**；管理员可以在侧边栏的 **数据源** 中添加更多，例如每个产品一个只读副本，或者单独的分析库。每个检查只读取其中一个数据源。

## 添加数据源

1. 打开 **数据源**，点击 **添加数据源**。只有管理员可以操作，其他人只能查看列表。
2. 填写名称。ID 会根据名称自动生成，保存前可以修改；检查通过这个 ID 引用数据源。
3. 粘贴 URL 格式的连接串：`postgres://user:password@host:5432/database?sslmode=require`。
4. 点击 **测试连接**。Assay 会在只读事务中连接并读取一次，显示 PostgreSQL 版本和所用账号。如果这个账号在任何地方有写权限（超级用户、`pg_write_all_data`、表的写权限或数据库的 `CREATE` 权限），结果会提醒你：检查只需要 `SELECT`，请为 Assay 创建只读账号（见 [SQL 安全规则](/docs/sql-safety)）。
5. 点击 **保存**。连接串加密保存，之后不再显示，管理员也看不到；列表只显示 `user@host:port/database`。

之后要更换连接，在该行的菜单中选择 **编辑** 并粘贴新的连接串；留空则保留当前连接。行上的 **测试** 会测试已保存的连接，并把结果显示在该行。

## 在检查中使用

有多个数据源时，检查编辑器（新建检查页面，以及 **管理检查** 中的 **编辑**）会显示 **数据源** 字段。它决定检查在哪个库执行，也决定模板选择器列出哪些表，以及 AI 助手从哪个库读取表结构、在哪个库试运行草稿。只有内置数据源时不显示这个字段，所有检查都使用它。

把检查改到另一个数据源和其他修改一样：修改别人的检查需要审批，编辑历史会记录这次变更。检查页面的标题下方会显示它的数据源，**覆盖情况** 页面也可以切换数据源。

## 删除数据源

在行菜单中选择 **删除** 可以删除没有检查使用的数据源。仍有检查使用时，Assay 会告诉你有几个，请先把它们改到其他数据源。内置数据源来自环境变量，请在环境中修改 `DATABASE_URL`。

## 连接串规则

- 只接受 `postgres://` 或 `postgresql://` 格式的 URL，参数只能是 `sslmode`、`channel_binding`、`application_name`、`options` 和 `connect_timeout`。
- **拒绝内网主机**：10.x、172.16–31.x、192.168.x、回环地址、链路本地地址（包括云元数据地址），以及 `localhost`、`*.internal` 这类名称。每次连接都会重新检查地址，因此之后被解析到内网的域名也无法连接。数据库在内网的自托管部署可以设置 `ALLOW_PRIVATE_DATA_SOURCES=true`（见 [环境变量](/docs/environment-variables)）。
- 公网主机**必须验证 TLS**（证书和主机名），没有写 `sslmode` 时也一样。只有在允许内网主机时，内网主机才能使用 `sslmode=disable`。
- 服务器需要 `ASSAY_SECRET_KEY` 才能保存数据源；有检查使用新增数据源后，GitHub Actions 定时执行也需要它（见 [定时执行](/docs/scheduling)）。

## 给 AI 代理

MCP 服务器的 `list_data_sources` 工具会列出每个数据源的 ID、名称和类型，`list_checks` 和 `get_check` 会说明检查使用哪个数据源（见 [API 密钥与 MCP](/docs/api-keys)）。
