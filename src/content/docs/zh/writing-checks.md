# 编写检查

点顶栏右侧的**新建检查**。

## 编辑器

在左边写查询。上方工具栏可以：

- **AI**：描述你要找什么，让 AI 起草 SQL。见 [AI 助手](/docs/ai-assistant)。
- **Format**：整理 SQL 格式。
- **Preview**：保存前先检查查询。

编辑器下方的状态栏会立即告诉你这段 SQL 能不能用：*Read-only, ready to save*，或者不能用的原因。

## 详细信息

| 字段 | 说明 |
|---|---|
| **名称** | 各处显示的名字，必填。 |
| **Script ID** | 根据名称自动生成，只含小写字母、数字和连字符，用在链接和历史里。 |
| **描述** | 这个检查在找什么、为什么重要。 |
| **范围** | 覆盖的数据范围，比如 *orders*。 |
| **标签** | 最多 8 个，用于分组和筛选。 |
| **作者** | 默认是你的账号。 |
| **定时** | 打开后按 cron 表达式定时执行，见[定时执行](/docs/scheduling)。 |
| **中文翻译** | 可选的中文名称、描述和范围。 |

## 怎样写好一个检查

- **返回需要有人去修的行**，并带上找到它们所需的列（ID、日期、金额）。
- **保持够快。**检查有 30 秒时间（看起来会跑很久的查询有 5 分钟），超时会被数据库取消。
- **只读。**任何写入、加锁或修改设置的语句都会被拒绝，见 [SQL 安全规则](/docs/sql-safety)。

```sql
-- 同一客户在 5 分钟内下了金额相同的订单
SELECT a.id, b.id AS duplicate_id, a.customer_id, a.total
FROM orders a
JOIN orders b
  ON b.customer_id = a.customer_id
 AND b.total = a.total
 AND b.id > a.id
 AND b.created_at - a.created_at < interval '5 minutes';
```

## 保存之后

如果你不是管理员，新检查要等审批通过后才会执行。每次保存还会记录一个版本，可以查看改了什么并回滚。

## 找出还没被检查的表

侧边栏里的 **覆盖情况** 列出数据库里的每张表，以及有多少个检查读取它。没有检查的表排在最前；选中后点 **为这张表新建检查**，编辑器会带着一段起始查询打开。标为 *缺失* 的表被某个检查读取，但数据库里已经没有了，这个检查在修改之前都会失败。

覆盖情况根据每个检查的 `FROM` 和 `JOIN` 统计，只是概览：只在函数调用里用到的表不会被计入。
