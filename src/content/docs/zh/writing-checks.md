# 编写检查

点顶栏右侧的**新建检查**。

## 从模板开始

编辑器上方的 **从模板开始** 可以直接写出大多数表都需要的检查。选择一个模板和一张表，再选它需要的列和设置，查询、名称、检查 ID 和描述（中英文）都会自动填好，之后仍可随意修改。提示里的 **撤销** 可以恢复之前的草稿。

| 模板 | 找出 |
|---|---|
| **缺失值** | 某一列为空（NULL）的行。 |
| **重复** | 一个或多个键列的取值出现在不止一行。和唯一约束一样，键中含空值的行不计入。 |
| **悬空引用** | 某列指向另一张表中不存在的值的行，例如客户已不存在的订单。 |
| **数据新鲜度** | 最新的时间早于设定的小时数，或者表是空的，此时返回一行。 |
| **超出范围** | 小于最小值或大于最大值的数字，上下限都可以不设。 |
| **意外取值** | 不在允许列表中的取值，每行一个，按文本比较。可以选择是否允许为空。 |

选择器只列出数据库报告的表和列，并且只提供适用于该模板的列（新鲜度用时间列，范围用数字列）。**覆盖情况** 里的 **为这张表新建检查** 会带着选好的表打开这个页面。

## 编辑器

在左边写查询。上方工具栏可以：

- **AI**：描述你要找什么，让 AI 起草 SQL。见 [AI 助手](/docs/ai-assistant)。
- **格式化**：整理 SQL 格式。
- **预览**：保存前先检查查询。

编辑器下方的状态栏会立即告诉你这段 SQL 能不能用：*Read-only, ready to save*，或者不能用的原因。

## 详细信息

| 字段 | 说明 |
|---|---|
| **名称** | 各处显示的名字，必填。 |
| **检查 ID** | 根据名称自动生成，只含小写字母、数字和连字符，用在链接和历史里。 |
| **描述** | 这个检查在找什么、为什么重要。 |
| **范围** | 覆盖的数据范围，比如 *orders*。 |
| **标签** | 最多 8 个，用于分组和筛选。 |
| **作者** | 默认是你的账号。 |
| **定时** | 打开后按 cron 表达式定时执行，见[定时执行](/docs/scheduling)。 |
| **中文翻译** | 可选的中文名称、描述和范围。 |

## 怎样写好一个检查

- **返回需要有人去修的行**，并带上找到它们所需的列（ID、日期、金额）。
- **保持够快。**整段 SQL 默认有 30 秒时间（`CHECK_TIMEOUT_MS`），超时会被数据库取消。
- **只读。**任何写入、加锁或修改设置的语句都会被拒绝，见 [SQL 安全规则](/docs/sql-safety)。

```sql
-- 同一客户在 5 分钟内下了金额相同的订单
SELECT a.id, b.id AS duplicate_id, a.customer_id, a.total
FROM orders a
JOIN orders b
  ON b.customer_id = a.customer_id
 AND b.total = a.total
 AND b.id > a.id
 AND b.created_at - a.created_at < interval '5 minutes';
```

## 保存之后

如果你不是管理员，新检查要等审批通过后才会执行。每次保存还会记录一个版本，可以查看改了什么并回滚。

## 找出还没被检查的表

侧边栏里的 **覆盖情况** 列出数据库里的每张表，以及有多少个检查读取它。没有检查的表排在最前；选中后点 **为这张表新建检查**，编辑器会带着一段起始查询打开。标为 *缺失* 的表被某个检查读取，但数据库里已经没有了，这个检查在修改之前都会失败。

覆盖情况根据每个检查的 `FROM` 和 `JOIN` 统计，只是概览：只在函数调用里用到的表不会被计入。
